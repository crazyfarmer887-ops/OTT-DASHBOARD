# GButs Dify customer support — operations

Owner requested24/7 GButs support on the existing server, initially shadow drafts, then only validated automatic responses. Refund/replacement decisions and unresolved issues go to the existing GButs topic of @GTHelpPlzBot.

## Architecture and scope

Dedicated systemd `gbuts-support.service` and localhost-only Dify1.18.0 API workflow; main AIO is unchanged on a65fe88. The three-node Dify workflow takes anonymized enum facts, calls the private authenticated inference tool, and returns a strict plan. Existing backend verifies buyer/order/seller/room, chooses the versioned fixed Korean template, owns SEND receipts and Telegram escalation. Dify has no account/refund/family mutation tool. The initial deployment is API-only: no public Dify console, vector database, autonomous shell, plugin runtime or separate customer widget.

The scope is currently accessible, verified purchased subscription 1:1 rooms for Netflix, Disney+, YouTube, Spotify, MSOffice, iQIYI and WeTV. It does not claim product comments or unverified prospective-buyer chats. Existing code/invite/Notion delivery requests remain delegated to their existing specialized workers. Those workers get at least60seconds before support considers a reply, and a newer seller response cancels support's plan. No existing credential/template/repost/member settings were changed. Existing general buyer-message Telegram monitoring is preserved; support adds reviewed human-handoff summaries rather than replacing that monitor.

Approved initial replies: find earlier delivered account instructions; ask the device and displayed login error; for already delivered Netflix/Disney accounts, one bounded app/browser restart guide; acknowledge a resolved issue. Explicit refund, exchange, dispute, uncertain data, repeated failed guidance or at most two support turns require human review. Handed-off rooms stay paused until explicitly resumed in private state; writing to the notification bot does not itself send a buyer reply.

Support defaults to anonymous Kilo `kilo-auto/free`, with no paid fallback enabled. Kilo documents 200 free requests per IP per hour; anonymous `PROMOTION_MODEL_LIMIT_REACHED` is a rate-limit response, not subscription expiry. Validation/retry traffic exhausted the shared IP allowance. Do not infer a paid authorization from that error. Optional provider code has explicit authorization and budget guards but is not configured in production.

Only allowlisted service/intent/device labels, delivery boolean and bounded turn count leave the server. Customer text, emails, IDs, links, passwords, codes and cookies never reach inference. Arbitrary model text cannot become a customer reply; malformed output or disagreement fails closed. Financial, uncertain and specialized delivery decisions are rules-first without inference. Correct high-confidence model plans are cached for identical anonymous facts, exact policy/instructions and provider route for24hours. A429 stops immediate retries and puts new uncached Kilo calls on a conservative one-hour local cooldown; this is not a promise of the provider's precise reset time. Cached results remain usable. Unavailable inference goes to operator review.

## Private files and controls

`/home/ubuntu/.config/gbuts/support/` is0700 and runtime/config/receipts are0600. `runtime.json` contains private Dify/tool keys; never print it. `config.json` has mode draft/auto/paused, startAt, autoSince and policyVersion. `journal.json` contains hashes, fixed outgoing templates, receipts, rounds and paused rooms, not original customer messages or credentials. Changing config invalidates a pending SEND's final permission check. `validation.json` contains only anonymous evaluation metadata and case hashes. Old failed first-pass validation is preserved privately.

A promotion must use `promotionAllowed` from the committed engine against the exact approved workflow ID and policy version, at least24 fixtures, at least12 real inquiries, zero unsafe/invalid cases and all safe cases correctly recognized. Also require an actual healthy recent worker scan and retained draft/no historical sends. Switch config startAt and autoSince to the promotion time; never replay pre-activation drafts. Keep the current source/templates in sync with policy version and repeat validation after behavior changes.

Pause by setting config.mode=paused. Global AIO safe mode also blocks replies. A handed-off room is owned by the operator, not resumed merely because another buyer message arrives. Operational resumption requires reviewing the exact order/room and removing that room's pause; preserve all attempted/confirmed receipts. Never clear an attempted SEND to retry: query saved messages, confirm its exact text in the same room, or hand off. Native GButs timestamps have second precision; confirmation tolerates only that precision within the persisted attempt's second.

Handoff notifications use the existing GButs bot/topic and an incident-specific key. Failed Telegram notifications retry; known delivered handoffs do not spam. Persistent worker failures and platform-rejected rooms have separate bounded operational alerts. Notification bot authentication was verified with read-only getMe, not a test customer message.
