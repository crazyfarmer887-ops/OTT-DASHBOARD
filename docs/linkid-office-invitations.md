# 링키드 Office 365 초대 운영 절차

2026-10-19 사용자가 지정한 이후 초대 작업의 기본 절차다.

## 처리 순서

1. 링키드의 로그인 계정, 서브 프로필, 파티, 구매자를 확인하고 해당 구매자가 마지막으로 요청한 Microsoft 이메일을 확인한다.
2. 아이폰 미러링의 시엔위 대화에서 해당 주문용 Office 365 링크를 연다. 구매한 이용 기간과 사용 가능한 링크인지 확인한다. 주문별 발급 링크와 지정된 구매자 이메일을 연결한다.
3. 시엔위 링크의 신청 페이지에 구매자 이메일을 입력하고 초대 링크를 발급받는다.
4. 결과 페이지에서 **`https://aka.ms/…` Microsoft 초대 링크**를 그대로 가져온다.
5. 링키드 앱의 해당 파티에서 **파티원 프로필 → 초대 링크 보내기/등록 → `aka.ms` 링크 입력 → 확인** 순서로 등록한다. 완료 기준은 링크 등록 성공과 해당 파티원의 ‘초대 완료’ 표시다.
6. 같은 구매자의 1:1 채팅에 동일한 `aka.ms` 링크와 아래 안내를 보낸 뒤 채팅에 저장됐는지 확인한다.

> 초대 링크 보내드립니다. 아래 링크에서 요청하신 Microsoft 계정으로 로그인하신 뒤 초대를 수락해 주세요.
> [발급된 aka.ms 링크]

초대 링크 발급·전달과 구매자의 수락·구독 활성화를 구분해 보고한다. 구매자의 계정으로 수락하는 단계는 구매자가 진행한다.

## 확인 및 재개

- 아이폰 미러링이 잠겨 있으면 사용자에게 잠금 해제를 요청하고, 가능한 동안 링키드 요청 이메일과 파티 연결을 확인한다.
- 구매자·파티·계정·프로필 연결과 최신 이메일을 등록 직전에 다시 대조한다. 주문용 링크가 이미 다른 이메일에 연결된 경우 올바른 주문용 링크를 확인한다.
- 이전 처리 기록과 채팅을 읽어 이미 등록·전달된 초대의 중복 처리를 방지한다. 결과가 불확실하면 현재 저장 상태를 조회해 확인한다.
- 운영 기록에는 파티·파티원·채팅 식별자, 처리 단계, 링크/문구 해시, 확인 시간과 메시지 식별자를 저장한다. 로그인 토큰과 구매자별 초대 URL은 공개 문서나 알림 로그에 기록하지 않는다.

## 확인된 링키드 웹 계약 (2026-10-19)

공식 웹 클라이언트의 파티원 초대 링크 등록은 `/api/party/sendRegistLink`에 `{ sid, partyid, targetUid, link }`를 전송하며 성공 시 `result: 0`과 해당 파티원의 `needreg: 0`을 확인한다. 실제 `aka.ms` 링크를 전달하는 이 단계가 프로필 초대 등록에 해당한다. `/api/party/confirmmembshareid`의 완료 확인만으로 링크 등록까지 완료됐다고 판단할 수 없다.

운영 API를 이용할 경우에도 앱과 같은 구매자 연결 및 링크 등록 계약을 지키며, 전용 세션으로 서브 프로필을 확인하고 요청 간격을 유지한다. 채팅은 저장된 본문과 발신자·대상 방을 다시 조회해 검증한다.

이 문서는 이후 요청 시 사용할 운영 절차를 정한 것이다. 상시 자동 초대 작업의 활성화 여부와는 별개다.
