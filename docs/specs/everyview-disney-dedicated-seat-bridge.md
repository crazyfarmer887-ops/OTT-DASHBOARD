# Everyview dedicated Disney seat bridge (local scaffolding)

Each mapped Everyview party may reserve one specific profile on its account, including profile 6. The reservation remains counted against GButs even if the Everyview advertisement is hidden, a buyer joins, the buyer disappears, or a provider read fails. A disappeared or replaced buyer is not treated as a confirmed refund. A hash of the observed buyer identity prevents silently treating a different person as the same buyer. No existing profile assignment is changed.

The bridge requires a pre-existing explicit account/party mapping and an independently verified one-buyer party capacity, roster timestamp and open-advertisement count. `visibleEmptySlots` alone does not prove that a vacancy can be purchased. Unknown or stale evidence, inconsistent roster, an existing unrecognized reservation, an already occupied party that still advertises a vacancy, or changed buyer identity produces an incomplete snapshot, which existing GButs inventory guards must reject. Prior unrecognized claims are retained rather than dropped. Applying a snapshot must occur inside the existing shared inventory lock with an atomic write.

A read-only evidence collector checks seller ownership, account binding, the buyer-facing profile guide, global visibility checkbox/label, server `CURRENT_MEMBER_CNT`, the checked state and labels of individual empty-slot switches, and the current roster. It fails closed if any disagree; an empty-name CSS class alone is not evidence of a purchasable slot. The `everyviewDedicatedEvidenceReader` function can be supplied to `runDisneyDedicatedBridge`; the latter writes all account snapshots atomically through the caller's existing inventory lock. The real observed provider markup sometimes uses a plain `pld-slot-name` class for buyers, which the shared detail parser now supports.

An opt-in runtime adapter loads `/home/ubuntu/.config/gbuts/everyview-disney-inventory.json` and stores a restricted, atomic status journal alongside it. The config is version 1 with `enabled` and a `parties` array containing explicit `partyId`, `accountEmail` and `profileNumber`. It starts only with `EVERYVIEW_DISNEY_INVENTORY_ENABLED=true`; a missing config or safety pause stays paused. It uses the existing private Everyview cookie, seller error alert and `withGbutsOttInventory` lock. Each cycle first observes owned parties, then verifies evidence against the same roster and persists held snapshots; a failed read immediately writes incomplete snapshots when the journal and mapping remain readable. It has not been registered in `server.ts` or enabled in production.

The dedicated model does not guarantee atomic checkout across independent platforms, and never opens or closes a real party. Before activation, verify the real party capacity and listing visibility, bind profiles and buyers, ensure all GButs sale/repost paths reserve the same seat, test failure recovery, and only then start publishing. Automatic reopening after a refund remains blocked until the refund, buyer removal and advertisement state can be independently verified.
