# Everyview Disney restart recovery and publication gate

Status: local, disabled scaffolding. Do not publish while the provider creates an immediately visible party without proven pre-armed monitoring. A review of the live official create form found no initial visibility setting in its `party` object; the ability to create hidden has not been demonstrated. Registering a monitor after POST or retrying on process restart cannot eliminate the initial exposure gap.

`recoverDisneyMonitoring` is a read-only-on-provider recovery runner for records whose provider party ID was already durably recorded. It verifies seller ownership, account and 6번 guidance, then, under the same AIO in-process inventory lock, holds the dedicated profile before idempotently adding the cutoff and inventory monitoring records. Interrupted local config writes can be replayed. It never re-submits creation, never infers a refund, and does not re-enable paused monitoring. It is not registered in `server.ts` and defaults off.

An attempted submission without a saved provider ID remains held. The default diagnostic only reads the seller's party list. The API exposes no known request idempotency key or provider-side correlation token, so a party that merely resembles the request is not enough for automatic promotion.

The local publishing adapter now supports a 12-hex-digit random request marker in the buyer-visible title, stored with the full title, seller-list baseline, pre-armed monitoring intent and seat reservation in a single shared inventory write before the single POST. A read-only recovery requires one and only one new seller-owned result with that exact marker and title, exact account, plan, 30-day term, price, 6번 instructions and email access; zero, multiple, incomplete or stale results stay held and never trigger another POST. A crash between the shared inventory write and the legacy journal write is recoverable from the stored intent. After an independently verified match, startup recovery reconciles the cutoff and inventory config idempotently. Synthetic tests cover timeout, duplicate candidates and restart recovery. A pre-armed enabled monitoring configuration may initially have no party IDs; the watcher remains paused until the ID is reconciled.

One live read-only comparison found that a pre-existing 25-character title is fully preserved between seller card and seller detail. This does not establish that newly created random markers are always preserved or that seller-list pagination/async loading cannot hide results. No provider POST was sent to establish these facts. The marker does not solve visible-on-create exposure or permit a retry when no match is found.

The monitoring intent and reserved 6번 place are atomic in the shared store, but cutoff and inventory runtime configurations are separate files and cannot become bound to a real ID until that ID is returned or securely recovered. Their repair is idempotent, not an atomic guarantee of zero exposure time. Configuration and journal changes must be durable and serialized inside the AIO process, not in a separate CLI with its own in-process lock. The startup recovery requires `EVERYVIEW_DISNEY_RECOVERY_ENABLED=true` and a factory supplied with the GButs runtime dependency to perform exact read-only correlated recovery; both remain off until explicitly configured.
